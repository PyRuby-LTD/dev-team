# EPIC-005 Historic activity import

**Depth: deferred - gated on a spike**

Bringing activities recorded before sync was enabled into on-track.

Deferred because it is not simple and cannot be scoped yet. The spike in
`scope.md` must report first: can we establish what has already been uploaded,
is there a reliable last-upload date, and does the answer differ for historic
activities?

That spike is not only about history. Any unattended sync needs to know what it
has already delivered, so its finding also bears on EPIC-001's reliability.
