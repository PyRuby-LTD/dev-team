---
name: technical-writing
kind: rule
description: How every role writes work items, findings, questions and pull requests
---
- Write for a reader who knows the codebase and the glossary. Do not explain
  glossary terms.
- Use the glossary's terms, not synonyms for them.
- Lead with the point.
- Do not restate what is already said elsewhere in the item, and do not pad.
- Keep it to a few lines.
- A story describes expected behaviour in non-technical terms; the API
  contract fragment is the exception.
- Code comments only explain code that is surprising or complicated.
